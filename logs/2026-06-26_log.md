## 15:50 WIB — Fix BUG utilisasi: input lot menimpa utilisasi lama ("record terhapus")

### Gejala (dilaporkan user, contoh KJK)
- KJK GL BORON: Obtained 1.400, Used 950, Available 450 (di kartu dashboard).
- Saat buka form input utilisasi: tampil **0 / 1.400 used, Available 1.400** → "record seakan terhapus". Jika Simpan lot → utilisasi 950 ketimpa nilai lot, available membengkak.

### Root cause (sistemik, bukan KJK saja)
- Model **`util = Σ lot`** dipakai di frontend & backend. Tapi **32 dari 33 baris produk** punya utilisasi di `company_product_stats` (dari master import) dengan **lot kosong** (lotUtil=0). Jadi:
  - Display: "used" dihitung murni dari lot (0) → tampil 0/obtained, available=obtained. (gejala "terhapus")
  - Save: `patchCompanySheets` set `utilization = Σ lot` → **menimpa** utilisasi otoritatif (950 → nilai lot).

### Fix — baseline preservation (`util = baseline + Σ lot`)
Baseline = utilisasi di stats yang belum dipecah jadi lot = `max(0, statUtil − Σlot)`. Lot baru **menambah**, bukan menimpa.
- **Backend** `server.js` `patchCompanySheets`: snapshot `oldLotSums` (Σ util_mt lot pra-patch); `effUtil = max(0, prevUtil − oldLotSum) + newLotSum` (ganti `utilization = lotSum`). Guard util=0 (anti-zeroing 2026-06-12) dipertahankan.
- **Frontend** `10-edit-form.js`: helper `utilBaselineForProd` (cache per-co, `==null` guard) + `effectiveUtilForProd`.
- **Frontend** `11-shipment.js`: display used/avail, validasi kuota (onSalesDirectChange + saveSalesUtil), badge available, grand total, dan recompute live (`co.utilizationByProd`) semua pakai `effectiveUtilForProd`.
- **Frontend** `08-drawer.js`: clear `co._utilBaseline` saat data fresh server mendarat (openDrawer refresh) → baseline re-capture.
- Bump versi: `08-drawer v13`, `10-edit-form v4`, `11-shipment v8`.

### Verifikasi
- **Simulasi node** recompute backend (7 skenario): ALL PASS — KJK input 450 → util 1.400/avail 0; idempotent re-save; edit 450→300 → 1.250/150; company sehat (lot=util) tidak double-count; produk baru; over-quota floor avail 0.
- **Served files**: `effectiveUtilForProd` ada di JS ter-serve; index.html versi ter-bump.
- **Browser (read-only, tanpa save)**: form KJK kini tampil **Available 450 MT**, **950 / 1.400 MT used**, Total 950/1.400 — cocok dengan kartu dashboard. Gejala "terhapus" hilang.
- **Commit/Deploy:** `2eb45fc` · Heroku **v93** · origin synced.

### Catatan
- Belum di-test save end-to-end di produksi (untuk hindari mengubah data KJK tanpa perlu). Saat user benar-benar input 450 (kebutuhan asli), hasil yang diharapkan: util 950→1.400, available 450→0. Bisa diverifikasi setelahnya.
