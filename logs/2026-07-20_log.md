# Log — 2026-07-20

## 09:05 WIB — IKM utilisasi "2" bukannya 2000 (locale bug pada input MT)

- **Gejala:** Kartu IKM (produk GI ALLOY, HS 7225.92.90) menampilkan `Obt 4.150 · Used 2 · 4.148 MT · 0% utilized`. Seharusnya utilisasi 2000 MT.
- **Root cause:** Browser user ber-locale id-ID (kartu render "4.150" dengan titik = pemisah ribuan). Di `public/js/11-shipment.js`, `buildSalesRow` (dan input ops-real + reapply) mengisi `value=` input MT dengan `toLocaleString()` **tanpa argumen locale** → pada id-ID jadi `"2.000"`. Saat disimpan ulang, `saveSalesUtil` / `onSalesDirectChange` / `onOpsRealChange` hanya strip koma lalu `parseFloat("2.000")` = **2**. Jadi setiap re-save nilai 2000 diam-diam korup jadi 2 — itu sebabnya "gak berubah-berubah".
- **Bukti:** repro round-trip di scratchpad — `(2000).toLocaleString('id-ID')` = "2.000" → `parseFloat("2.000".replace(/,/g,''))` = 2 (bug); `'en-US'` → "2,000" → 2000 (fix).
- **Ubah (kode):** paksa `toLocaleString('en-US')` di 3 prefill input MT (util-direct, ops-real, reapply target) — konsisten dengan `fmtThousandInline` yang memang selalu format en-US, sehingga koma yang di-strip cocok.
- **File/Tab:** `public/js/11-shipment.js` (baris 209, 287, 901).
- **Commit/Deploy:** `29e819d` · Heroku **v118** (push origin + heroku, verifying deploy done).
- **Ubah (data):** koreksi lot tersimpan `company_shipments` row 56 (IKM / GI ALLOY / lot 1) `util_mt` **2 → 2000**, `updated_at` di-bump. Sheet: "Mater Data IQ Dash" (`1t4MbpW…MYd0`). Script: `migration_work/fix_ikm_util.js` (guard cek IKM/GI ALLOY sebelum tulis).
- **Verifikasi:** live `/api/data` → IKM `utilizationMT:2000`, `utilByProd["GI ALLOY"]:2000`, obtained 8000, available 6000. Kartu GI ALLOY kini Used 2.000 / 2.150 MT (~48% utilized).
- **Catatan sisa (belum di-fix, severity rendah):** `fmtThousandInline` masih memperlakukan titik yang **diketik** user sebagai desimal (ketik "2.000" gaya Indonesia saat mengetik → jadi "2.00"). Bug utama (korupsi diam-diam saat re-save dari prefill) sudah tuntas; input-UX dot-as-thousands terpisah dan berisiko bentrok dengan entri desimal, jadi tidak diubah kali ini.
